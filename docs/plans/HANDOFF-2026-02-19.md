## T014 — Create Staging Supabase Project

**Nature**: Entirely manual infrastructure task. No code changes to `src/`. Involves Supabase dashboard, Vercel dashboard, and updating `.env.staging` with real values.

**Reference**: `docs/staging-setup.md` (full workflow reference)

### What needs to happen

#### Step 1 — Create Supabase staging project

1. Go to https://app.supabase.com
2. Create new project: `coaching-animator-staging`
3. Choose the same region as production
4. Wait for database to initialize (~2 min)
5. Note down from **Settings → API**:
   - **Project URL** → `https://xxx.supabase.co`
   - **anon key** → `eyJhbGci...`
   - **service_role key** → `eyJhbGci...`
6. Note down from **Settings → Database**:
   - **Connection string** → `postgresql://postgres:[PASSWORD]@db.xxx.supabase.co:5432/postgres`

#### Step 2 — Apply migrations to staging

8 migration files in `supabase/migrations/`, chronological order:

```
20260131130000_online_platform.sql          ← core tables (users, animations, etc.)
20260131130100_add_thumbnail.sql            ← thumbnail column
20260131130200_add_moderation_blocklist.sql ← moderation tables
20260131140000_fix_relationships.sql        ← FK fixes
20260201000000_add_max_animations.sql       ← quota columns
20260216000000_drop_legacy_tables.sql       ← drops shares/follows (v2.0 Phase 0)
20260216120000_collections_and_video.sql    ← collections + video_url (v2.0 Phase 1)
20260216120100_version_history.sql          ← animation_versions table + trigger (v2.0 Phase 1)
```

**Option A — Supabase CLI (recommended)**:
```bash
# Link to staging project (need project ref from dashboard URL)
npx supabase link --project-ref your-staging-project-ref

# Push all migrations
npx supabase db push
```

**Option B — Manual via Supabase SQL Editor**:
Run each migration file in order in the Supabase SQL Editor (copy/paste each file's contents).

**Verify**: After applying, check in Table Editor that these tables exist:
- `user_profiles`, `saved_animations`, `animation_versions`, `collections`, `collection_items`

#### Step 3 — Update `.env.staging` with real values

File: `.env.staging` (already exists, fill in the placeholders)

```bash
NEXT_PUBLIC_SITE_URL=https://coaching-animator-staging.vercel.app  # or your staging URL
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co       # from Step 1
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci...              # from Step 1
SUPABASE_SERVICE_ROLE_KEY=eyJhbGci...                  # from Step 1
DATABASE_URL=postgresql://postgres:[PASSWORD]@db.xxx.supabase.co:5432/postgres
```

Do **not** commit the filled-in `.env.staging` to git (it contains secrets). Keep it local only.

#### Step 4 — Configure Vercel staging environment (if desired)

Two options:

**Option A — Vercel Preview Deployments** (simplest):
Every PR auto-deploys a preview. Configure the preview environment in Vercel to use staging Supabase keys:
1. Vercel Dashboard → Project → Settings → Environment Variables
2. Add all variables from `.env.staging`
3. Set scope to **Preview** only (not Production)

**Option B — Dedicated staging branch**:
```bash
git checkout -b staging
git push origin staging
```
Configure the `staging` branch in Vercel as an additional production branch with its own env vars.

#### Step 5 — Verify staging works

```bash
# Test against staging (swap .env.local to point at staging Supabase)
npm run dev
```

Smoke test checklist:
- [ ] User can register and log in
- [ ] User can create and save animation
- [ ] My gallery loads saved animations
- [ ] Public gallery loads
- [ ] Collections page (`/collections/[id]`) loads
- [ ] Version history modal opens from my-gallery card
